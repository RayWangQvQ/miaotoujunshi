## Explained divergences

### `chat_csv/blank-row-inside`

A row whose fields are all blank is not a row on the Dart side and is a row of empty values on the Python side. `csv.dart` states the rule and its reason: Python's `DictReader` keeps a line of bare commas, and a reader that kept it would go on to refuse the whole import with 存在空消息 about a line that holds nothing. macOS therefore rejects the file; the domain ignores the line and reads the two real rows. Neither draws a wrong candle, and the difference only exists for a CSV a human edited by hand — every generated export fills `timestamp` and `message`. The domain keeps its rule, which is the one Android's hand-written parser stated, because a refusal that names a message the user cannot find is worse than skipping nothing.

```json
dart:   {"candles": [{"close": 0, "date": "2026-08-01", "events": [], "high": 1, "low": 0, "mine": 1, "open": 0, "other": 1}], "id": "blank-row-inside", "messages": 2, "ok": true}
python: {"id": "blank-row-inside", "ok": false}
```

### `csv_grid/empty-fields`

The same rule, seen from the writer: a grid whose row is all empty fields does not survive a round trip through `parseCsvGrid`, because the row is not a row. Python's `csv` module returns it. This is the only fixture where the two sides' CSV layers disagree, and it is the one the domain chose deliberately — the alternative is the 存在空消息 refusal above. No candle or chat row is all-empty: a candle always carries a date and a chat row always carries a timestamp.

```json
dart:   {"back": [["a", "b", "c"]], "id": "empty-fields", "round_trip": false}
python: {"back": [["a", "b", "c"], ["", "", ""]], "id": "empty-fields", "round_trip": true}
```

### `profile/missing-optional-fields`

The domain's `Profile` is typed, so a field cannot be absent — an unfilled one is the empty string. macOS's profile is a dict, and `validate_profile` refuses a key that is missing outright. No caller on either side ever produces a partial profile: macOS builds one with `empty_profile()` and fills it from the store, and the domain's own `Profile.empty` sets every field. The fixture therefore exercises a state the migrated side cannot represent, which is why it is recorded rather than reconciled.

```json
dart:   {"context": {"goal": "自然接话", "label": "阿七", "stage": "了解中"}, "id": "missing-optional-fields", "ok": true}
python: {"context": null, "id": "missing-optional-fields", "ok": false}
```

### `update/current-shorter-than-latest`

Two-digit versus three-digit version tags. Python compares tuples, where `(1, 2) < (1, 2, 0)`, so a build running `1.2` is told that `1.2.0` is an update. The domain compares segment by segment and treats the shorter form as the missing-zero form, so `1.2` and `1.2.0` are the same release and nothing is reported — see `Version.isStrictlyOlderThan`. This is a deliberate correction made while converging three ports: the Windows port is the only one that compared versions, it has only ever tagged `x.y.z`, and the domain's reading is the one that cannot announce a release the user is already running.

```json
dart:   {"id": "current-shorter-than-latest", "reports": false, "tag": null}
python: {"id": "current-shorter-than-latest", "reports": true, "tag": "1.2.0"}
```
